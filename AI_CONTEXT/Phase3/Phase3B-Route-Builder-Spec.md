# Phase 3-B · Route Builder Specification

> **Status:** Design — V1.1 Implementation Target
> **Principle:** Supervisor builds route. System records decision. Templates emerge later.

---

## 1. Three Modes

| Mode | Availability | Source | When |
|------|:----------:|--------|------|
| Mode 1: Manual | ALWAYS | Factory Capability Catalog | Day 1 |
| Mode 2: History Copy | After 5+ orders | Previous order route_snapshot | Week 1+ |
| Mode 3: Template | Phase 4 ONLY | Auto-generated from 30+ snapshots | Month 3+ |

**Day 1 default: Mode 1 (Manual). Only mode available.**

## 3. Mode 2 — History Copy

### When Available
After supervisor has created 5+ orders.

### Flow
```
1. Supervisor selects source order from dropdown
   (filtered by: same customer, or same spec, or recent 20)
2. System loads that order's route_snapshot.steps
3. Pre-selects all previously selected processes
4. Supervisor adjusts (add/remove) for this order
5. Creates new order with source="history"
```

## 4. Mode 3 — Template (Phase 4)

### NOT in V1.1
Templates are generated by the system after 30+ snapshots accumulate. Supervisor reviews and approves. Never pre-loaded.

## 5. Route Saving

```
On [Create Order]:
  route_snapshot = {
    source: "manual" | "history",
    snapshot_at: timestamp,
    steps: [{seq, process_code, process_name, dept_name, selected}]
  }
  
  order_nodes generated for selected=true steps only.
  First node: status='active', rest: 'waiting'.
  Seq: gap-based (10, 20, 30...).
```
