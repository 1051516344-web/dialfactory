# DialFactory V1 · Factory Reality Gap Analysis

> **状态：** Strategic Review
> **目的：** 判断 V1 系统是否匹配广州表盘工厂真实生产环境
> **方法：** 逐项对比 V1 能力 vs 工厂需求 vs 行业标准
> **输出：** 系统定位 + V1.5/V2 路线

---

## 1. System Positioning — What DialFactory Actually Is

### 1.1 Positioning Matrix

| 系统类型 | 典型能力 | DialFactory V1 |
|---------|---------|:--------------:|
| **ERP** | 财务、采购、库存、HR、客户关系 | ❌ 全部没有 |
| **MES** | 设备对接、实时采集、自动排产、产能计算 | ❌ 全部没有 |
| **MES 子系统** | 单一模块（如质量管理、工单管理） | ⚠️ 部分覆盖 |
| **生产追踪工具** | 订单在哪、卡了多久、有什么问题 | ✅ **就是这个** |
| **纸质跟单本替代** | 数字化记录、可视化流程、可查询 | ✅ **核心价值** |

### 1.2 正确定位

```
DialFactory V1 = 生产追踪工具 (Production Tracking Tool)

不是 ERP。
不是 MES。
是纸质跟单本的数字化替代品。

核心价值:
  Q1: 订单现在在哪？
  Q2: 卡了多久？
  Q3: 为什么停？
  Q4: 谁经手的？
  Q5: 历史发生过什么？
```

这与 V1 Scope (9-V1-Scope-Definition.md) 的定义完全一致。

## 2. V1 6-Page Coverage Analysis

### 2.1 跟单员核心工作覆盖

| 跟单员日常工作 | V1 页面 | 覆盖度 | 缺失 |
|-------------|---------|:----:|------|
| 早上巡线：各订单在哪 | P1 Dashboard + P2 List | 80% | 无"我的关注"列表 |
| 创建新订单 | P3 Order Create | 70% | 无模板时流程阻塞 |
| 推进工序状态 | P4 Order Detail | **90%** | 缺少撤销按钮 |
| 记录质量问题 | P4 → 记录异常 | 80% | 类型列表可能需要扩充 |
| 处理返工 | P4 → 返工/追加 | **95%** | — |
| 查看工艺路线 | P5 Route List | 40% | 只读，无法调整路线 |
| 汇总异常 | P6 Exception List | 60% | 无法按订单/部门/日期筛选 |
| 客户催单时回答 | P4 Order Detail | **95%** | — |
| 下班前检查 | P1 Dashboard | 70% | 无"今日完成"统计 |

### 2.2 核心流程覆盖度

```
订单创建 → 节点推进 → 异常记录 → 返工 → 完成
   70%        90%        80%       95%     90%

整体覆盖度: ~85%
阻塞点: 无模板时无法创建订单
```

## 4. V1.5 应该进入的功能

### 4.1 优先级排序

| 优先级 | 功能 | 原因 | 依赖 |
|:------:|------|------|------|
| **P0** | Route Builder (3 modes) | 🔴 阻塞订单创建 | 无 |
| **P0** | Undo (5min window) | 🟠 操作错误无法回退 | 无 |
| **P0** | +cancelled 状态 | 🟠 基本业务操作 | Migration 002 |

### 4.2 V1.5 定义

```
V1.5 = V1.0 + Route Builder + Undo + Cancelled + Route Editor

```

## 5. 不应该自己开发的功能

### 5.1 交给 ERP 的能力

| 功能 | 原因 |
|------|------|
| 财务管理 | 不是生产追踪范畴 |
| 采购管理 | 粗胚/物料采购属于供应链 |
| 库存管理 | 需要完整的进销存模型 |
| 人力资源管理 | 排班/考勤/薪酬 |
| 客户关系管理 (CRM) | 客户合同/报价/对账 |

**DialFactory 不替代 ERP。但它可以向 ERP 提供生产进度数据。**

### 5.2 交给 MES 的能力

| 功能 | 原因 |
|------|------|
| 设备数据采集 | 需要 PLC/传感器集成 |
| 自动排产 | 需要产能模型+约束求解 |
| 实时生产看板 | 需要设备层数据 |
| 过程质量控制 (SPC) | 需要测量数据自动采集 |
| 物料追溯 (批次/序列号) | 需要全链路数据 |

**DialFactory 不替代 MES。但它是 MES 的"轻量入口"——从人工录入开始，逐步自动化。**

### 5.3 永远不应该自己开发

| 功能 | 原因 | 替代方案 |
|------|------|---------|
| 自建后端服务器 | Supabase 已提供完整 BaaS | — |
| 自建数据库 | Supabase PostgreSQL 已够用 | — |
| 自建认证系统 | Supabase Auth (V2 启用) | — |
| 移动原生 App | PWA 可覆盖平板场景 | V1.5 PWA |
| 复杂报表引擎 | Excel/Google Sheets 导出即可 | V2 导出 |
| 消息推送 | 微信/钉钉群机器人 | V1.5 通知 |

## 6. 系统定位宣言

### DialFactory 是什么

```
DialFactory 是：
  ✅ 生产追踪工具 — 回答"订单在哪、卡了多久、为什么停"
  ✅ 纸质跟单本替代品 — 数字化记录、可视化流程
  ✅ 轻量级单部门工具 — V1: 1-2个跟单员
  ✅ 质量事件记录器 — 异常类型+数量+处理方式

DialFactory 不是：
  ❌ ERP — 不做财务/采购/库存
  ❌ MES — 不做设备对接/自动排产
  ❌ BI 工具 — 不做深度数据分析
  ❌ 协同平台 — 不做消息/审批流
  ❌ 移动 App — 不做原生应用
```

### 价值边界

```
┌─────────────────────────────────────────────────────┐
│                   DialFactory                        │
│                                                     │
│  解决: 生产透明化                                    │
```

## 7. 结论

### 7.1 V1 是否满足工厂需求？

```
核心追踪能力 (Q1-Q5):  ✅ 85% 覆盖
阻塞问题:             🔴 无模板时无法创建订单
操作体验:             🟠 缺少撤销 + 取消订单
管理能力:             🟡 路线编辑/异常统计缺失

综合判断: V1 可以作为"最小可用版本"上线试用，
         但需 Phase 3-B 修复 3 个阻塞问题后才能交工厂使用。
```

### 7.2 建议路线

```
当前:   V1.0 已部署 (https://1051516344-web.github.io/dialfactory/)
        ↓
3-B:    V1.1 阻塞修复
        + Route Builder + Undo + Cancelled
        ↓
3-C:    真实数据迁移 (16 customers + 35 processes)
        ↓
交付:   交工厂跟单员试用 (1-2周)
        ↓
V1.5:  Route Editor + 部门待办联动 + 异常统计
        ↓
V2:    外协 + 首件 + 统计 + 多用户 + 审计日志
```

### 7.3 对工厂的建议

```
1. 提供 2-3 条常用路线（完整步骤列表）
   → 否则 V1.1 只能用"工序构建"模式

2. 确认 35 道工序的部门归属
   → P16电镀在制二已确认，其他待确认

3. 用无痕窗口试一下现有系统
   → https://1051516344-web.github.io/dialfactory/
   → 感受一下流程（虽然Demo数据是虚构的）

4. 准备好接受"数字化跟单本"而非"全自动MES"
   → DialFactory 不是来替代跟单员的判断
   → 是来帮跟单员记住"那500件货现在到哪了"
```
