# DialFactory System · 数据库设计原则

## 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| 数据库类型 | PostgreSQL | 成熟、免费、支持JSON |
| 托管 | Supabase | 免费层够用，自带API和认证 |
| 本地缓存 | IndexedDB | 离线可用，浏览器原生 |

## 命名规范

| 规则 | 示例 |
|---|---|
| 表名：`snake_case` 复数 | `orders` `order_nodes` `exception_events` |
| 主键：`id` UUID | `id UUID PRIMARY KEY DEFAULT gen_random_uuid()` |
| 外键：`{table}_id` | `order_id` `process_id` |
| 时间戳：`_at` 后缀 | `created_at` `started_at` `ended_at` |
| 布尔值：`is_` 前缀 | `is_required` `is_deleted` |

## 核心原则

### 1. 事件日志优先

所有状态变更用追加式记录，不用覆盖式。每次推进、异常、移交都新增一条 `audit_log`。撤销 = 回滚到前一条。

### 2. UUID 替代索引

`order_nodes` 的关联用 UUID，不依赖数组索引。插入/删除节点不影响其他节点的引用。

### 3. 冗余适度

`order_nodes` 表里存 `dept_id` 和 `process_name`，即使 `processes` 表后续改名也不影响已记录数据。

### 4. 不强制外键

`exception_events.node_id` 不强制外键约束——节点可能被删除，但异常记录要保留。

### 5. 不可变数据

`processes` 表的数据一旦有订单使用，不可修改、不可删除。只能新增版本或标记 `is_active=false`。

## 禁止事项

- 不在数据库里嵌 JSON 数组（V13 的 `issues` 和 `nodes` 数组就是反例）
- 不存枚举字符串——用 `type_code` 等短码
- 不暴露 Supabase API key 在前端——通过 Row Level Security 控制
- 不做复杂触发器/存储过程——逻辑放在应用层
