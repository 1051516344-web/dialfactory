# DialFactory System · 核心业务模型

## 模型总览

```
订单 Order
  ├── 基本信息（订单号、客户、数量、底质、电镀色）
  ├── 选择路线模板 Route
  │     └── Route = 工艺节点 Process[] 的排序组合（建议模板）
  ├── 跟单员确认/调整工序（Phase 0-A.2）
  │     └── 必修工序不可取消，其余可逐项确认或跳过
  ├── 生成节点 OrderNode[]
  │     └── 每个节点对应一条 Process（仅 confirmed=true 的工序）
  │     └── 节点有状态：waiting / active / done / paused（V1 四态）
  │     └── 节点记录时间、数量、部门
  ├── 节点可动态追加（Phase 0-A.2）
  │     └── 生产过程中可插入任意工序节点（返工/重洗/退回重做）
  └── 节点可关联异常事件 ExceptionEvent
        └── 类型、数量、处理方式
```

## 订单结构

| 字段 | 说明 | 来源 |
|---|---|---|
| 订单号 | 唯一标识 | 录入 |
| 客户 | 17个客户之一 | 选择 |
| 粗胚数量 | 投产数 | 录入 |
| 订单数量 | 含损耗系数 | 录入 |
| 底质处理 | 无底纹/太阳纹/CD纹 | 选择 |
| 电镀颜色 | 如银白60s | 录入 |
| 喷砂类型 | -/重砂/轻砂/中砂 | 选择 |
| 路线 | 关联 Route | 选择 |
| 状态 | 生产中/暂停/完成 | 自动计算 |
| 创建时间 | 系统记录 | 自动 |

## 工艺节点（Process）独立于订单

> **V1 范围：** 6 个核心字段（code, name, type, default_dept_id, is_required, is_active）。返工策略/首件确认/排队特性/质量重要度延后至 V1.5+。

| 字段 | 说明 | V1 |
|---|---|---|
| 编号 | P01-P99 | ✅ |
| 名称 | 工序名称 | ✅ |
| 类型 | 加工/辅助/检验 | ✅ |
| 默认部门 | 通常由哪个部门执行 | ✅ |
| 是否必选 | 必修工序任何路线不可取消 | ✅ |
| 是否启用 | 停用旧工序保留编号 | ✅ |
| 返工方式 | 不可逆/局部返工/完全返工/仅分流 | ❌ V1.5+ |
| 首件确认 | 是/否 | ❌ V2 |
| 排队特性 | 是（等什么）/否 | ❌ V2 |
| 质量重要度 | 高/中/低 | ❌ V2 |

## 状态流转规则（V1 四态）

```
waiting ──→ active ──→ done
              │
              └──→ paused ──→ active
```

> **Phase 0-A.2 备注：** V1 移除 handing_off 状态（仅外协场景需要，外协不在 V1）。内部部门间流转使用 `active → done` + 自动激活下游 `waiting → active`。
