### 2.2 流程字符串读取规则

以 `二车二网球车电四网四 蓝/白 350 银白/深灰 516 胶圈 四 OK` 为例：

```
二车二网球车电四网四   蓝/白 350   银白/深灰 516   胶圈 四   OK
│                     │           │               │        │
│                     └─颜色/数量对─┘               │        └─确认标记
│                                                  └─胶圈组件在制四
└─工序路径: 制二→车床→制二→网印→球印→车床→电镀→制四→网印→制四
```

**规则：**
1. 数字（一/二/三/四）表示部门转换点
2. 连续的"部门+工序"表示顺序执行
3. 颜色描述 + 数字 = 该颜色/规格的数量
4. 组件标记（胶圈/铜圈）+ 部门 = 该组件在该部门处理

## 三、关键业务模式

### 3.1 多规格（Multi-Spec）—— 普遍现象

**几乎每张订单都包含多个颜色/规格变体。** 这是 V1 模型最大的未覆盖维度。

示例：

```
生产编号 45138：上二车二球车四 搪黑/银白 1380  搪蓝/银白 212  下 球四  2500
→ 同一生产编号包含 3 个变体（搪黑/银白 1380 + 搪蓝/银白 212 + 下层 2500）

生产编号 45679：二球四 半消光浅蓝贝壳 40 白贝/金 50 白贝/玫 30
→ 同一生产编号包含 3 个贝壳变体

生产编号 45829：一二球四 黑 20700 蓝 13000 绿16100 银白12500 黑蓝 2100
→ 同一生产编号包含 5 个颜色变体，总计 64,400 件
```

**对 V1 的影响：**
- `orders.order_qty` 无法表达——总数量是各变体之和，但每个变体可能有不同的颜色/表面处理
- `orders.base_texture` / `plate_color` / `sand_type` 三个固定字段完全不够用
- 每个变体是否独立追踪工序？还是整批一起走？

> ❓ **Q-DD-01**：同一生产编号下的不同颜色变体是**整批一起流转**还是**分批独立流转**？例如 45138 的"搪黑/银白 1380"和"搪蓝/银白 212"是同时推进还是分别推进？

### 3.2 多层结构（Multi-Layer）—— 确认存在

**53 张订单（11%）有上/下层分离路线。**

模式：
```
上 [上层路径] → 半消光XX QTY
下 [下层路径] → 半消光YY QTY
组装
```

典型示例：
```
Row 21: 上 车二网球四 银白 303 下 四 香槟 303   组装
       上层: 车床→制二→网印→球印→制四 → 银白 303
       下层: 制四 → 香槟 303
       汇合: 组装

Row 29: 上 二球车电四球四 下 二车二球四  消光 6018 169 4127 329 圈 二网球四
       上层: 制二→球印→车床→电镀→制四→球印→制四
       下层: 制二→车床→制二→球印→制四
       汇合: 圈组件→制二→网印→球印→制四
```

**对 V1 的影响：**
- Phase 0-A.2 预留的 `order_nodes.layer` 字段触发条件已满足
- `second_route_id` 可能是合理的——上下层路线经常不同

> ❓ **Q-DD-02**：上下层的工序执行是**并行推进**还是**先后推进**？跟单员是同时追踪两条路线吗？
> ❓ **Q-DD-03**：上层的"组装"和下层最后的节点——它们之间是什么关系？上层做完+下层做完→一起组装？

### 3.3 库存挪用（Inventory Reuse）—— 系统化操作

**49 张订单（10%）涉及"挪用"。** 这不是边缘 case，是常规操作。

挪用分两种模式：

**模式 A：全部挪用（订单"不生产"）**
```
Row 104: CES 45789 不生产 一二车二球四 黑/灰 1800 挪用 45479
         → 完全不做，全部从 45479 库存取
```

**模式 B：部分挪用（自产 + 挪用混合）**
```
Row 209: TIF 45911 505 网球四网四 光蓝 652 消光黑 505 挪用 45825
         → 自产 505 + 挪用 45825 的库存
```

**模式 C：多源头挪用**
```
Row 116: FAF 45804 不生产 挪用 44687.45187
         → 从两个不同订单挪用
```

**挪用和被挪用的关系链：**
```
45180 → 被 45811 挪用
45186 → 被 45816 挪用  
45187 → 被 45817 挪用
45407 → 被 45949 挪用
45479 → 被 45789, 45970 挪用（被多次挪用！）
45825 → 被 45911 挪用
45830 → 被 45950, 46098 挪用
45832 → 被 45985, 45988 挪用
```

> ❓ **Q-DD-04**：挪用后，被挪用的原订单的状态会变吗？比如 45479 被 45789 挪用后，45479 还是"完成"吗？
> ❓ **Q-DD-05**：挪用的产品是否已经过了所有工序直接可用？还是需要从某道工序开始继续加工？

### 3.4 "不生产"订单 —— 两种含义

48 张"不生产"订单实际上分两种：

| 类型 | 数量标记 | 含义 | 示例 |
|------|---------|------|------|
| 纯挪用 | `不生产` 在编号列 + `挪用 XXXXX` 在流程列 | 完全从库存取货，不走任何工序 | Row 116 "45804 不生产 挪用 44687.45187" |
| 零数量 | 数量列为 `不生产` | 暂停/待定/取消？ | Row 73 "45723 不生产 446" |

> ❓ **Q-DD-06**：数量列填"不生产"且流程列无"挪用"标记的行——这些订单是什么状态？是取消了吗？

### 3.5 生产编号规则

| 模式 | 含义 | 示例 |

| `NNNNNA` / `NNNNNB` | 同一客户订单的A/B拆分 | 45793A/45793B, 45820A |

## 四、V1 模型与真实数据的对照

### 4.1 已确认的 V1 设计

| V1 设计 | 真实数据验证 | 状态 |
|---------|------------|------|
| UUID 替代索引 | 流程路径极度非线性，插入/删除频繁（返工、追加、挪用） | ✅ 正确 |
| 动态追加节点 | 返工、挪用替代、外协插入——均需在流程中间插入节点 | ✅ 正确 |
| 路线模板 ≠ 生产路线 | 每张订单的流程字符串几乎都不同——不存在"标准路线"的完全复制 | ✅ 正确 |
| 人工确认工序 | 流程字符串由跟单员手工编写——说明工序确实是人工决定的 | ✅ 正确 |

### 4.2 被推翻的 V1 假设

| V1 假设 | 真实数据 | 影响 |
|---------|---------|------|
| 一张订单一种颜色 | **几乎每张订单多种颜色** | `plate_color` 单字段不够 |
| orders 表存颜色 | **颜色是变体级别的属性** | 颜色应挂在哪？ |
| 6-8 个节点 | **流程字符串密度暗示 10-30+ 个操作步骤** | order_nodes 数量预期翻倍 |
| 纯线性流程 | **上/下分叉 + 组装汇合 = DAG（有向无环图）** | seq 字段的单一线程不够 |

### 4.3 重要疑问

> ❓ **Q-DD-08（架构级）**：当前 V1 的 `order_nodes` 是纯线性序列（单 seq）。但真实流程是**上层路线 → 组装 ← 下层路线**的 DAG 结构。V1 是否需要支持"分叉+汇合"？还是可以在 V1 阶段把上下层作为同一 seq 序列的不同段落？
