## 一、架构审查结论

### 1.1 设计合理项（保留）

| # | 决策 | 依据 |
|---|------|------|
| A1 | 事件日志追加式存储 | 生产现场状态变更是不可逆事实。覆盖式存储无法审计。撤销 = 回滚 |
| A2 | UUID 替代数组索引 | nodeIdx 插入/删除后错位，UUID 永不错位且支持并发 |
| A3 | rework_pass 节点属性 + 动态追加 | 返工以 rework_pass 计数（同工序重做）+ 动态追加节点（任意工序）覆盖。独立表过度建模。Phase 0-A.2 确认：V1 不做自动返工路由，由跟单员人工决策 |
| A4 | exception_events 独立表 | 可查询、可统计、可跨订单聚合，优于嵌套数组 |
| A5 | handoffs 独立表 | 移交是完整业务事件（时间/数量/责任人/质量门禁），不应附属于节点 |
| A6 | 部门作为一等概念 | 有部门才有移交、质量门禁、责任归属 |
| A7 | 五态模型 → V1 四态 | V1 Scope 决策：取消 handing_off（仅外协场景需要，外协不在 V1）。保留 waiting/active/done/paused |
| A8 | PWA + IndexedDB 离线 → V1 删除 | V1 Scope 决策：工厂 WiFi 覆盖 + 4G 路由器即可保障在线。离线同步消耗的开发时间超过核心业务逻辑。V1.5 重新评估 |
| A9 | process_routes 版本控制 | 工艺演变不影响历史订单 |
| A10 | 不嵌套 JSON | 杜绝 V13 技术债复现 |

### 1.2 风险项及缓解措施

| # | 风险 | 等级 | 缓解 |
|---|------|------|------|
| R1 | 离线同步冲突：多用户离线修改同一订单 | 高 | 节点级操作天然无冲突；订单级字段用 `updated_at` 乐观锁；冲突保留双版本并标记 |
| R2 | 审计日志无限增长 | 中 | V1 不处理，预留 `archived_at` 字段。运营 6 个月后评估 |
| R3 | 数量链断裂：工人不填 qty_in/qty_out | 高 | QC 节点产出必填（应用层校验）。非QC节点不填不影响流转，统计时标记"数据不完整" |
| R4 | 外协过度简化 | 中 | 外协复用 order_nodes 结构，加 `is_outsourced` + `supplier_id` |
| R5 | 返工路由规则未定义 | 中 | processes 表增加 `rework_target` 字段，明确定义"回哪道工序" |
| R6 | RLS 策略设计滞后 | 中 | 建表同步定义 RLS，V1 最少角色集：admin / worker / viewer |

### 1.3 调整项

| # | 调整 | 原因 |
|---|------|------|
| C1 | `orders.status` 自动计算，不手动设置 | 消除不一致 |
| C2 | `order_nodes.status` 定义合法转换矩阵 | 防止非法状态跳转 |
| C3 | 新增 `first_piece_inspections` 表 | processes.need_first_piece 需要数据承载 |
| C4 | 新增 `customers` / `suppliers` 主数据表 | 17个客户、12家供应商不能靠字符串 |
| C5 | 外协复用 `order_nodes` | 外协是工序执行方式，不是独立概念 |
| C6 | 时间双轨：用户填写 + 系统记录 | 两者语义不同，都要保留 |
| C7 | 新增 `audit_logs` 表 | 设计原则已提，需在 ERD 体现 |
| C8 | 订单创建时快照路线为节点 | 路线修改不影响已创建订单。Phase 0-A.2 扩展：快照记录 `confirmed` 标记（跟单员确认/取消的工序） |

### 3.1 实体关系总览

```
    ▼                           │

    │                           │
    ▼                           │
processes ──────────────────────┘
    │
    ▼
departments ───────────── handoffs
```

### 3.2 核心聚合

#### 聚合根 1：订单（Order）
包含：基本信息 + 关联的所有节点 + 异常事件 + 移交记录
生命周期：创建 → 生产中 → 暂停 → 完成

#### 聚合根 2：工艺路线（Process Route）
包含：路线定义 + 多个步骤
生命周期：草稿 → 启用 → 停用

#### 聚合根 3：工艺目录（Process Catalog）
包含：独立于订单的工艺定义
约束：已被订单使用的工艺不可修改、不可删除，只能标记停用或创建新版本

### 3.3 订单状态机

```
                    ┌─────────┐
                    │ 生产中   │◄────────────────────────┐
                    │in_prod  │                         │
                    └────┬────┘                         │
                         │                              │
              ┌──────────┼──────────┐                   │
              ▼          ▼          ▼                   │
         所有节点    任一节点   任一节点                  │
         均为done   变为paused  均为waiting              │
              │          │          │                   │
              ▼          ▼          │                   │
         ┌────────┐ ┌────────┐     │                   │
         │ 完成   │ │ 暂停   │─────┘                   │
         │completed│ │paused  │                         │
         └────────┘ └───┬────┘                         │
                         │                              │
                         │ 任一节点恢复active            │
                         └──────────────────────────────┘

规则：
- 状态由 order_nodes 状态自动推导，不手动设置
- "完成" = 所有节点 status = 'done'
- "暂停" = 存在非 done 节点，且所有非 done 节点 status = 'paused'
- "生产中" = 其余情况
```

### 3.4 节点状态机（order_nodes）

```
                    ┌──────────┐
          ┌────────►│  active  │◄────────┐
          │         └────┬─────┘         │
          │              │               │
          │    ┌─────────┼─────────┐     │
          │    ▼         ▼         ▼     │
          │ ┌──────┐ ┌────────┐ ┌────────────┐
          │ │ done │ │paused  │ │handing_off │
          │ └──────┘ └───┬────┘ └─────┬──────┘
          │      ▲       │            │
          │      │       └────────────┘
          │      │              │
          │      │              ▼
          │      │         (resume)
          │      │
          │  (rework_pass++,
          │   new node created)
          │
          │  ┌──────────┐
          └──│ waiting  │◄── 上游节点完成移交后激活
             └──────────┘

合法转换矩阵：

| from        | to           | 条件                        |
|-------------|--------------|-----------------------------|
| waiting     | active       | 上游节点 handing_off→done   |
| active      | done         | 本工序完成                   |
| active      | paused       | 异常/暂停                    |
| active      | handing_off  | 准备移交下游                  |
| paused      | active       | 恢复                         |
| handing_off | done         | 下游接收                      |

禁止转换：waiting→done, paused→done, handing_off→paused, done→任意
```

### 3.5 返工路由规则（Phase 0-A.2 更新）

> **V1 Scope 决策：** 系统不自动执行返工路由。跟单员人工判断返工目标，通过两种方式执行。

**V1 保留：react_node（快捷操作）**
- 同工序重做 → rework_pass+1，插入原节点之后
- 适用于：电镀色差重镀、打磨返工

**V1 新增：动态追加节点（通用操作，Phase 0-A.2）**
- 在任意位置插入任意工序节点 → rework_pass=0（该工序首次执行）
- seq 自动重算：插入位置 N → 所有 seq ≥ N 的节点 seq += 1
- 适用于：退回前工序重做、追加清洗/检验、任何路线外临时工序

**V1 明确不做：** 5 种自动返工策略（none/repeat_node/back_to_prev/back_to_first/fork）作为 processes 表的 rework_strategy 字段。V1 不设此字段。人工决策替代系统自动路由。

**V1.5+ 延后：** AI 基于历史数据推荐返工目标工序。

## 四、数据库设计

### 4.1 完整表结构

#### 主数据表

```sql
-- 客户
CREATE TABLE customers (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        TEXT NOT NULL,
    code        TEXT,                          -- 短码，如 C01
    is_active   BOOLEAN DEFAULT true,
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- 供应商（外协）
CREATE TABLE suppliers (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        TEXT NOT NULL,
    contact     TEXT,
    is_active   BOOLEAN DEFAULT true,
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- 部门
CREATE TABLE departments (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        TEXT NOT NULL,                 -- 制一/制二/制三/制四/总QC
    type        TEXT NOT NULL,                 -- production / qc / external
    seq         INTEGER,                       -- 排序
    created_at  TIMESTAMPTZ DEFAULT now()
);
```

#### 工艺表

```sql
-- 工艺目录
CREATE TABLE processes (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code                TEXT NOT NULL UNIQUE,    -- P01-P99
    name                TEXT NOT NULL,
    type                TEXT NOT NULL,           -- 加工/辅助/检验/标记
    default_dept_id     UUID REFERENCES departments(id),
    is_required         BOOLEAN DEFAULT false,
    need_first_piece    BOOLEAN DEFAULT false,
    queue_character     TEXT,                    -- 排队特征描述，可空
    quality_level       TEXT,                    -- 高/中/低
    rework_strategy     TEXT DEFAULT 'none',     -- none/repeat_node/back_to_prev/back_to_first/fork
    rework_target_id    UUID REFERENCES processes(id), -- back_to_* 策略的目标工序
    is_active           BOOLEAN DEFAULT true,
    version             INTEGER DEFAULT 1,
    created_at          TIMESTAMPTZ DEFAULT now()
);

-- 工艺路线
CREATE TABLE process_routes (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        TEXT NOT NULL,
    dept_id     UUID REFERENCES departments(id), -- 起始部门
    version     INTEGER DEFAULT 1,
    is_active   BOOLEAN DEFAULT true,
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- 路线步骤
CREATE TABLE route_steps (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    route_id    UUID NOT NULL REFERENCES process_routes(id),
    process_id  UUID NOT NULL REFERENCES processes(id),
    seq         INTEGER NOT NULL,
    UNIQUE(route_id, process_id, seq)
);
```

#### 业务表

```sql
-- 订单
CREATE TABLE orders (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    order_no        TEXT NOT NULL UNIQUE,         -- 订单号
    customer_id     UUID REFERENCES customers(id),
    rough_qty       INTEGER,                      -- 粗胚数
    order_qty       INTEGER,                      -- 订单数（含损耗）
    base_texture    TEXT,                         -- 无底纹/太阳纹/CD纹
    plate_color     TEXT,                         -- 如 银白60s
    sand_type       TEXT,                         -- 重砂/轻砂/中砂/-
    route_id        UUID REFERENCES process_routes(id),
    route_snapshot  JSONB,                        -- 创建时快照路线名+工序名，用于显示
    status          TEXT DEFAULT 'in_production', -- in_production/paused/completed
    note            TEXT,
    created_at      TIMESTAMPTZ DEFAULT now(),
    updated_at      TIMESTAMPTZ DEFAULT now()
);

-- 工序节点
CREATE TABLE order_nodes (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    order_id        UUID NOT NULL REFERENCES orders(id),
    process_id      UUID REFERENCES processes(id),
    process_name    TEXT,                          -- 冗余：创建时快照工艺名
    process_code    TEXT,                          -- 冗余：创建时快照工艺编号
    dept_id         UUID REFERENCES departments(id),
    dept_name       TEXT,                          -- 冗余：创建时快照部门名
    status          TEXT DEFAULT 'waiting',        -- waiting/active/done/paused/handing_off
    seq             INTEGER NOT NULL,
    rework_pass     INTEGER DEFAULT 0,            -- 0=正常, 1=第1次返工...
    is_outsourced   BOOLEAN DEFAULT false,
    supplier_id     UUID REFERENCES suppliers(id),
    qty_in          INTEGER,
    qty_out         INTEGER,
    started_at      DATE,                          -- 用户填写
    ended_at        DATE,                          -- 用户填写
    note            TEXT,
    created_at      TIMESTAMPTZ DEFAULT now(),
    updated_at      TIMESTAMPTZ DEFAULT now()
);

-- 异常事件
CREATE TABLE exception_events (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    node_id         UUID NOT NULL,                -- 不设外键约束，节点删除后保留
    type            TEXT NOT NULL,                -- 色差/电镀不良/划伤/沙眼/变形/其他
    qty             INTEGER NOT NULL,
    severity        TEXT,                         -- 致命/严重/轻微
    resolution      TEXT,                         -- 返回磨板/返回电镀/重做/特采/报废/其他
    detail          TEXT,
    recorded_by     TEXT,
    created_at      TIMESTAMPTZ DEFAULT now()
);

-- 首件确认
CREATE TABLE first_piece_inspections (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    node_id         UUID NOT NULL REFERENCES order_nodes(id),
    result          TEXT NOT NULL,                -- pass / fail / conditional
    inspected_by    TEXT,
    detail          TEXT,
    created_at      TIMESTAMPTZ DEFAULT now()
);

-- 部门移交
CREATE TABLE handoffs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    order_id        UUID NOT NULL REFERENCES orders(id),
    from_dept_id    UUID REFERENCES departments(id),
    to_dept_id      UUID REFERENCES departments(id),
    from_node_id    UUID REFERENCES order_nodes(id), -- 上游完成节点
    to_node_id      UUID REFERENCES order_nodes(id), -- 下游接收节点
    qty             INTEGER NOT NULL,
    quality_gate    TEXT,                         -- pass / reject / conditional_accept
    handed_by       TEXT,
    accepted_by     TEXT,
    created_at      TIMESTAMPTZ DEFAULT now()
);

-- 审计日志
CREATE TABLE audit_logs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    entity_type     TEXT NOT NULL,                -- order / order_node / exception_event / handoff
    entity_id       UUID NOT NULL,
    action          TEXT NOT NULL,                -- create / update / delete / status_change
    old_value       JSONB,
    new_value       JSONB,
    performed_by    TEXT,
    created_at      TIMESTAMPTZ DEFAULT now(),
    archived_at     TIMESTAMPTZ                   -- 预留归档出口
);
```

### 4.2 索引策略

| 表 | 索引 | 用途 |
|----|------|------|
| orders | `(status, created_at)` | 状态筛选 + 时间排序 |
| orders | `(customer_id)` | 按客户查询 |
| order_nodes | `(order_id, seq)` | 订单节点列表 |
| order_nodes | `(dept_id, status)` | 部门待办查询 |
| order_nodes | `(supplier_id, status)` | 外协追踪 |
| exception_events | `(node_id)` | 节点异常列表 |
| exception_events | `(type, created_at)` | 异常类型统计 |
| handoffs | `(order_id)` | 订单移交历史 |
| audit_logs | `(entity_type, entity_id, created_at)` | 审计追溯 |
| audit_logs | `(created_at)` | 按时间查询日志 |

### 4.3 数据不可变规则

1. `processes` 已被订单使用的行，不可 DELETE、不可 UPDATE（除 `is_active` 外）
2. `process_routes` 同上规则
3. `exception_events` 不可修改、不可删除（只能新增修正事件）
4. `audit_logs` 只追加，不可修改、不可删除
5. `order_nodes` 只可修改 `status`、时间、数量、备注，不可修改 `process_id`、`dept_id`、`seq`
6. 订单完成（status='completed'）后，所有关联节点锁定

### 5.2 数据流

```
                    User Action
                         │
                         ▼
              ┌─────────────────────┐
              │   domain/ 层        │
              │   - 校验输入         │
              │   - 校验状态转换     │
              │   - 计算派生状态     │
              └─────────┬───────────┘
                        │
              ┌─────────▼───────────┐
              │   data/api.js       │
              │   - Supabase upsert │
              │   - 写入 audit_log  │
              └─────────┬───────────┘
                        │
              ┌─────────▼───────────┐
              │   data/cache.js     │
              │   - 更新 IndexedDB  │
              └─────────┬───────────┘
```

### 5.3 离线策略

```
在线模式：                        离线模式：
  UI                                UI
  │                                 │
  ▼                                 ▼
api.js ──► Supabase            cache.js ──► IndexedDB
  │                                 │
  ▼                                 ▼
cache.js (更新本地)            sync.js (操作入队)
                                   │
                                   ▼
                              恢复网络后
                              sync.js ──► api.js ──► Supabase
                                              │
                                              ▼
                                        冲突检测 (updated_at)
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                                 无冲突               有冲突
                              直接写入          保留双版本 + 通知用户

同步优先级：
1. 节点状态变更（高优先级，立即同步）
2. 异常事件（高优先级）
3. 时间/数量修改（中优先级）
4. 备注更新（低优先级，可批量）
```

### 5.4 组件接口规范

每个组件统一暴露两个函数：

```javascript
// 组件接口
{
    render(data, container),   // data: 该组件需要的数据子集
    update(data, container),   // 增量更新（仅变化部分）
    destroy(container)         // 清理
}
```

## 六、安全模型

### 6.1 角色定义

| 角色 | 权限范围 | 典型用户 |
|------|----------|----------|
| admin | 全部 CRUD + 工艺管理 + 用户管理 | 系统管理员 |
| worker | 本部门节点更新 + 异常记录 + 移交确认 | 跟单员、部门负责人 |
| viewer | 全部只读（含统计） | 管理层 |

### 6.2 RLS 策略（核心规则）

```sql
-- orders 表
-- admin: 全部
-- worker: 可读写，通过 dept 关联
-- viewer: 全部只读

-- order_nodes 表
-- admin: 全部
-- worker: 可读写本部门节点
-- viewer: 全部只读

-- exception_events 表
-- admin: 全部
-- worker: 可读写（通过 node → order_node → dept 关联）
-- viewer: 全部只读

-- processes / process_routes / route_steps 表
-- admin: 全部
-- worker: 只读
-- viewer: 只读

-- audit_logs 表
-- 所有人只读（不可修改审计日志）
```

### 6.3 前端安全

- Supabase anon key 可暴露（RLS 是真正的安全边界）
- 敏感操作（删除、工艺修改）需二次确认
- Service Worker 缓存不过期敏感数据（仅缓存工艺列表、部门列表等静态数据）

## 七、关键业务规则

### 7.1 订单创建（Phase 0-A.2 更新）

1. 选择路线模板 → 系统展示路线包含的全部建议工序
2. 跟单员确认/调整工序：必修工序（`processes.is_required=true`）不可取消，其余可逐项确认或取消
3. 快照确认结果：`route_snapshot = { route_name, steps: [{process_code, process_name, dept_name, seq, confirmed}] }`
4. 根据 `confirmed=true` 的工序生成 `order_nodes[]`
5. 初始节点：第一个节点 status='active'，其余 'waiting'
6. 记录 audit_log：`{entity: 'order', action: 'create'}`

### 7.2 节点推进

1. 校验当前状态允许目标转换（见 §3.4 转换矩阵）
2. 更新节点 status + 时间
3. 如果目标 = 'done' 且节点非最后节点：触发下游节点的状态变更检查
4. 如果目标 = 'handing_off'：创建 handoffs 记录，关联上下游节点
5. 重新计算 `orders.status`
6. 记录 audit_log

### 7.3 异常记录

1. 选择节点 → 填写异常类型/数量/严重度/处理方式
2. 异常数量不能大于节点产出数量
3. 记录 audit_log
4. 严重度为"致命"时，**不自动暂停节点**（人工决策），但 UI 闪烁红框提示

### 7.4 返工

1. 选择节点 → 确认返工 → 检查 `processes.rework_strategy`
2. 根据策略创建新节点或修改路由
3. 新节点 `rework_pass = 原.rework_pass + 1`
4. 原节点标记 `status = 'done'`（即使返工，原操作记录保留）
5. 记录 audit_log

### 7.5 移交

1. 上游节点 → handing_off → 创建 handoffs(quality_gate 待定)
2. 下游接收：更新 handoffs(quality_gate, accepted_by) → 上游节点 → done → 下游节点 → active
3. 拒收：handoffs(quality_gate = 'reject') → 上游节点回退到 active
4. 让步接收：handoffs(quality_gate = 'conditional_accept') → 正常流转 + exception_event（记录让步原因）
