## B. 说法正确但极易被误解（别按字面发挥）

| 说法 | 字面 | 实际约束 |
|---|---|---|
| 「订单状态由节点派生」 | 以为可以随便 UPDATE `orders.status` | 必须用 `OrderState.derive(nodes, currentStatus)`，**currentStatus 不能省**，否则已取消订单会被"复活" |
| 「巡检功能」 | 以为在 `orders` 上加个字段 | 独立表 `order_inspections`，**只 INSERT**。写 `orders` 会刷新 `updated_at`，毁掉"未推进时长"排序 |
| 「迁移文件在 supabase/migrations」 | 以为 push 就会执行 | **不会自动执行**，必须人工在 SQL Editor 跑；新迁移要幂等 + `NOTIFY pgrst, 'reload schema'` |
| 「Pages 自动部署」 | 以为所有文件都上线 | 只发布 `index.html css js sw.js`。新增根级静态文件必须改 `deploy.yml` 白名单 |
| 「改完刷新看看」 | 以为了立刻生效 | Pages 有 10 分钟缓存，必须硬刷新；判断线上是否新版要用 GET 比对 |
